# ODBCKit implementation plan

Final text/ABI decision: use only narrow ODBC text APIs with an explicit UTF-8
driver contract. No SQLWCHAR buffer or UTF-16-width assumption is used, so iODBC's
different wide-character width is outside this implementation. Native builds
assert pointer/SQLLEN/SQLULEN and SQLBIGINT widths at compile time. Only the Linux
x86_64 bridge is shipped; the sealed archive contains no Windows or macOS runtime,
and native execution on those platforms remains unverified. Link/import libraries are generated by the builder where
needed, rather than listed as a nonexistent source-package input.

Deliver an ODBC 3 backend implementing Buoy Database and RowSet. A small C bridge
uses the public ODBC API with SQLPrepare/SQLBindParameter/SQLExecute. Values never
enter SQL text. Support NULL, signed 64-bit integers, Double, Boolean and UTF-8
text. Return bounded buffered rows so cursor lifetime does not retain driver
statements. Bound columns, rows, cells and parameter count; reject truncation.
Expose structured SQLSTATE/native error codes, affected row counts, explicit
transaction methods and configurable last-insert-id SQL (ODBC has no portable
identity query). LastInsertId without a configured expression throws explicitly.

Start with Linux unixODBC and a real temporary SQLite ODBC database. Build a
native bridge for supported host targets; compiler-check Buoy public surface on
all six desktop targets. Driver manager and database-specific drivers are system
requirements, never installed or configured by importing the package. An ODBC
connection may target MySQL with an installed MySQL driver, but this is not a
standalone native MySQL backend.

Risks: driver-dependent Unicode ANSI encoding, NULL and text truncation, SQLLEN
width, connection/statement ownership, autocommit and transaction behavior,
secret leakage in connection diagnostics, typed helpers requiring LastInsertId.
Explicitly limit supported drivers to UTF-8 narrow APIs; wide APIs are outside
this version. Preserve exact DECIMAL text instead
of silently rounding. Reject binary columns until an explicit binary API exists.

Validation: actual compiler JSON for every authored Buoy file and target branch;
sealed-package runtime consumer covering typed values, injection-looking values,
64-bit signed extrema, NULL, Unicode, transaction rollback/commit, duplicate-column
ambiguity, bounds, errors, repeated close/reconnect and unsupported identity query.
Compare against SQLite through ODBC, not an emulated backend. Native C builds use
strict warnings; run ASan/UBSan where feasible. Mac/Windows native execution must
remain explicitly unverified without real hosts.
